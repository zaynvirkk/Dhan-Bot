## Verify the trader candidate without touching the live process

Use an isolated checkout on a normal machine or the VM. Do not run verification
against the production state directory: its verification command first removes
any existing verification marker. Install Python 3.12+, Node.js 18+, the locked
Python requirements, and the candidate package in that checkout's virtualenv.
Then run, from the candidate's repository root:

```bash
DHAN_VERIFY_STATE=$(mktemp -d /tmp/dhan-candidate-verify.XXXXXXXX)
DHAN_BROKER_READ_ONLY=1 .venv/bin/dhan-cas verify --state-dir "$DHAN_VERIFY_STATE"
```

This must pass the complete test suite, the real localhost HTTP/WebSocket cases,
and all fifteen production-source mutation checks. The earlier in-process tests
are supplementary. A manually created marker or skipped network cases cannot
substitute for this command. These tests use synthetic broker accounts; passing
establishes software behavior, not profitable execution or a live route proof.
